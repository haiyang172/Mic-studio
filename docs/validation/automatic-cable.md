# 自动虚拟线路匹配 · 0.2.1

日期：2026-10-29（Australia/Sydney）。

本机只读检查发现：标准 CABLE Input/Output 两端均可用，工作区保存的发送端编号已不在当前设备列表。旧代码仅在 `CableOutputId == null` 时选择发送端，导致驱动重新安装后持续提示未就绪。

新流程在设备刷新和用户开始处理前，用当前枚举快照匹配同一条线路。有效旧选择优先；失效时自动选择完整标准线路，再按稳定顺序选择其他完整线路。不会混用不同家族、不同声道标签的端点，不以物理扬声器代替虚拟线路。无完整线路时保留原选择并说明原因。默认单条线路直接显示自动连接就绪，多条完整线路才显示可选的更换入口。

软件不会因为自动匹配而开启实体麦克风、恢复中断的录音、改变 Windows/其他软件默认输入，或换用其他实体麦克风。用户仍通过开始/停止控制处理。当前正在运行的旧版窗口没有被测试终止，也没有直接改写其个人工作区。

验证：

- WindowsAudio 39 项合成/空闲检查通过，新增 11 项覆盖有效旧选择、过期编号、枚举顺序、不可用端点、跨线路、物理设备排除和重复端点等情况。
- WPF 32 项控件检查、27 种布局通过。新增应用层检查覆盖过期编号自动修复、接收端消失、重建后的新编号及不可用麦克风禁止替换；使用隔离工作区，未打开音频。
- `--resolve-cable` 只读检查当前真实枚举，可用失效的模拟编号匹配现有线路，不输出设备编号、不保存设置、不采集。
- 发布脚本支持经过限定格式校验的版本目录，构建新便携版时保留正在使用的旧目录。

复验：`scripts/Build.ps1`、`scripts/Test-UI.ps1`、`.tools/dotnet/dotnet.exe run --project tests/MicStudio.WindowsAudio.Tests -c Release -- --tests-only`；实际只读线路检查使用 `--resolve-cable`。
