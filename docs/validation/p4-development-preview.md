日期：2026-10-29（Australia/Sydney）。用户确认没有签名证书，先交付可测试的开发预览。完整 P4 的签名部署和真实系统音频验收继续保留。

## 已实现

- 真正的 x64 原生 `MicStudioApo.dll`，实现 COM 工厂、APO 配置/实时/系统效果接口、浮点格式协商、透传、增益、八段 EQ、限幅及固定 −6 dB 测试模式。它与第三方配置适配器 `MicStudio.Apo.dll` 是不同组件。
- 每录音端点独立的 224 字节参数快照、序号校验、协商格式通配、进程所有权和心跳。关闭当前控制器会停用参数；心跳不续期超过 3 秒时透传。实时回调不分配内存、不等锁、不读文件或网络。
- 托管编码/映射写入、只读身份与签名检查、指纹化部署预览、明确 UAC 管理程序、受保护备份与保守还原。没有可信签名时不提供系统安装动作，不放宽受保护音频策略，不覆盖外部效果。
- 界面有独立原生预览模式与设备页状态；“参数已发送”“已绑定”和“系统音频已生效”分别处理，始终保留实际响应待验证。断开设备、格式变化或租约丢失停止当前控制。

## Discord 外部监听问题

用户报告外放或 Discord 麦克风测试时回声并持续尖锐啸叫。播放声再次被麦克风收进并反复回放，会形成声学反馈；把外部播放送进同一 CABLE 还可能形成数字回路。限幅只约束采样峰值，不能切断反馈。

只读检查观察到 Discord 的 CABLE 输入和物理语音输出；同时某条 Discord 播放流位于 CABLE。会话统计无法证明该流属于语音、测试还是其他播放，不能据此擅自改写已正确的语音输出。没有改变 Discord 设置或系统默认设备，没有中断现有使用，也没有启动麦克风测试。

- 本地/CABLE 输出新增持续高强度窄频啸叫保护，在 DSP 后、线路/监听/处理后录音分流前执行，独立于效果旁路。触发后清空待播队列并静音，需主动停止/重新开始；不循环自动解除。
- 单独的 `MicStudioEcho.dll` 使用官方 SpeexDSP 1.2.1。WASAPI loopback 提供物理播放参考，使用有界时间历史、重采样和每麦克风声道的 10 ms 自适应处理。参考失效、切换、原生错误或库缺失时明确报告并透传，不使用陈旧参考。
- 参考仅在用户开始处理且功能开启时采集，不保存、不上传。该链路仅处理经过 Mic Studio 的本地/CABLE 信号；Discord 选择原始物理麦克风时会绕过它。自研 APO 预览暂不包括这一桌面参考处理或桌面啸叫保护。
- 这是外放消回声开发预览。WASAPI 回调时间估计、设备时钟漂移、非线性扬声器和真实双讲尚待设备测试。持续大音量单音或口哨可能触发保护；不能宣称所有回声或啸叫均可消除。

构建：`scripts/Build-NativeCpp.ps1` 需要 Windows x64 C++/SDK/CMake，Windows CI 已提供。`scripts/Build.ps1` 仍只要求 .NET。生成原生库后运行 `scripts/Stage-NativeRuntime.ps1`，再运行 WindowsAudio 的 `--echo-native-tests`、`scripts/Test.ps1` 和 `scripts/Test-UI.ps1`。发行脚本要求原生文件存在并捆绑原始 SpeexDSP 声明，不把缺少 AEC 库的包作为完整预览发布。

原生源码、受控部署器和合成测试不代替 Windows 系统加载、目标端点隔离、真实音频响应、签名分发及安装/卸载回滚验收。正式 P4 仍未完成；本轮不注册未签名组件、不重启音频服务、不更改保护策略。
